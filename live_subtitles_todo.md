# TODO: Локальные живые субтитры с переводом на русский

## Цель

Сделать приложение для Fedora + Hyprland (Wayland), которое захватывает звук из видео/браузера/плеера и показывает поверх окна **живые русские субтитры**. Приоритет — качественный перевод английской речи, включая технические доклады по программированию, ИБ и реверс-инжинирингу. Обработка по умолчанию локальная, без отправки аудио в облако.

## Целевая среда

- Fedora Linux, Hyprland, Caelestia shell.
- RTX 4060 Laptop, 8 ГБ VRAM; CPU i5-12450H.
- PipeWire; Python + `uv` предпочтительны для прототипа.
- Не требовать отдельного плеера: работа с Firefox, VLC, другими приложениями.

## MVP (сделать сначала)

- [ ] Исследовать существующие решения (в том числе whisper-overlay, translation-overlay) и возможность переиспользовать компоненты; не завязываться на них без проверки совместимости с Wayland.
- [ ] Реализовать захват **звука выбранного приложения или системного выхода** через PipeWire, без захвата микрофона по умолчанию. Проверить сценарий с Bluetooth-наушниками и сменой аудиоустройства.
- [ ] Добавить VAD и буферизацию фрагментов речи; сохранять временные метки и уметь обрабатывать непрерывную речь.
- [ ] Реализовать ASR на английском: `faster-whisper` (`small.en` / `medium.en` как стартовые варианты), запуск с GPU, измерение задержек/нагрузки. Предусмотреть замену ASR-движка.
- [ ] Сделать отдельный переводчик EN → RU с контекстом последних реплик. Стартовый кандидат: небольшая Qwen в GGUF через `llama.cpp`; проверить, какую модель реально можно запускать одновременно с ASR в пределах 8 ГБ VRAM.
- [ ] Сделать прозрачный субтитровый оверлей для **Wayland/Hyprland** (например, Qt/QML + слой через совместимый layer-shell; проверить поддержку). Нужны position, масштаб, перенос строк, контрастная подложка, режим без перехвата мыши.
- [ ] Подключить хоткей включения/отключения (через `hyprctl`/конфигурацию Hyprland), предусмотреть интеграцию в Caelestia позже.
- [ ] Обеспечить очистку/замену предыдущей строки и устойчивое поведение при паузах в речи, переключении окна и аудиоустройства.

## Качество перевода — ключевое требование

- [ ] Не переводить изолированные слова: давать переводчику завершённые фразы и контекст (например, 5–10 последних реплик).
- [ ] Ввести глоссарий технических терминов с правилами «переводить / оставлять на английском / сохранять аббревиатуру»: `heap`, `stack`, `payload`, `race condition`, `use-after-free`, `reverse shell`, `syscall`, `IDA`, `call graph` и т. д.
- [ ] Добавить профили предметной области: «Общий», «Программирование», «Кибербезопасность / реверс»; опционально — автоматическое определение темы.
- [ ] Сохранять идентификаторы, названия библиотек, команды, пути, имена функций и код без бессмысленной локализации.
- [ ] Проверить случаи ошибок ASR (`cache`/`cash`, `SQL`/`sequel`, аббревиатуры). Не заставлять переводчик выдумывать исправления: при неуверенности сохранять оригинальный термин.
- [ ] Реализовать переключатель **«только русский / оригинал + русский»** (двуязычный режим важен для технических видео).
- [ ] Сравнить LLM-перевод со специализированным MT и, при возможности, с SeamlessM4T v2 на реальных записях; выбрать движок по качеству, скорости и потреблению памяти, а не по названию модели.

## Производительность и UX (после MVP)

- [ ] Замерять отдельно latency: захват → конец фразы → ASR → перевод → отображение, а также VRAM, RAM и GPU/CPU utilization.
- [ ] Реализовать режимы «Быстро» и «Качественно»: меньший буфер vs. больше контекста. Задержку не обещать до замеров.
- [ ] Сохранять предыдущие субтитры краткое время и плавно обновлять текст, без дёрганья оверлея.
- [ ] Позволить вручную корректировать глоссарий и сохранять профиль для приложения/видео.
- [ ] Опционально экспортировать EN/RU-транскрипт в `.srt` / `.vtt` / `.txt` с таймкодами.
- [ ] Опционально: облачный API-перевод как **выключенный по умолчанию** режим с явным согласием на передачу текста.
- [ ] Опционально: системный трей/виджет Caelestia, настройка хоткеев и темы.

## Архитектура (ориентир, не жёсткое требование)

`PipeWire → audio capture → VAD/segmenter → ASR → context-aware translation → subtitle scheduler → Wayland overlay`

Компоненты должны иметь отдельные интерфейсы: `AudioSource`, `ASREngine`, `Translator`, `SubtitleRenderer`. Не блокировать UI инференсом; предусмотреть очереди, отмену устаревших задач и ограничение накопления задержки (backpressure). Явно различать предварительный и окончательный текст.

## Проверки и критерии готовности

- [ ] Англоязычный YouTube в Firefox без встроенных субтитров: появляется русский текст поверх видео.
- [ ] Русские субтитры читаемы в полноэкранном режиме Hyprland; оверлей не перехватывает ввод.
- [ ] В техническом докладе сохраняются смысл, термины, аббревиатуры, имена функций и библиотек; сравнить вручную минимум 10–15 минут примеров.
- [ ] Нет утечки памяти и растущего отставания после 30 минут просмотра; при высокой нагрузке старые фрагменты не накапливаются бесконечно.
- [ ] Работают переключение аудиоустройства, остановка/пауза, повторное включение и смена приложений.
- [ ] При отсутствии моделей/драйверов выводится понятная ошибка, а не молчание.
- [ ] Зафиксированы фактические средняя и p95 задержки, качество на выбранных тестовых фрагментах и потребление VRAM.

## Порядок работы для агента

1. Кратко изучить готовые решения и ограничения PipeWire + Wayland layer-shell.
2. Собрать вертикальный прототип: системный звук → ASR → перевод → текст в терминале; снять метрики.
3. Добавить Wayland-оверлей, хоткей и базовые настройки.
4. Оптимизировать сегментацию, контекст и технический глоссарий на тестовом наборе видео.
5. Реализовать двуязычный режим, сравнить альтернативные переводчики, зафиксировать результаты.
6. После стабилизации — интеграция с Caelestia и дополнительные функции.

**Важно:** сначала доказать приемлемую задержку и качество на 8 ГБ VRAM; не начинать с большого UI и не считать любые ориентировочные цифры производительности гарантией.
